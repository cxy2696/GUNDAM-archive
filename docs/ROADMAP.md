## 4. 下一阶段

1. **来源覆盖（最高优先级）**：给势力、人物、作品、地点、标签补 `source_refs`；把 B 级线索与 A 级核对分开显示。对应 `docs/GOVERNANCE.md` 的来源分级。
2. **检索增强**：拼音/罗马字模糊匹配、同义词与型号归一化；保持纯客户端与按需索引。
3. **性能与可访问性门禁**：接入 Lighthouse/视觉回归；为首屏 JS、长列表、3D 场景设定预算；补齐键盘与屏幕阅读器检查。
4. **内容扩量**：MSV、游戏原创、量产衍生与换装；坚持“有出处才收录”，不追求数字。
5. **资产管线**：在 `viewer/model.ts` 的 `partId / axis / order` 契约上接 glTF LOD0；程序化模型保留为回退。
6. **可选服务层**：只有出现实时编辑/多用户需求时才引入 API/DB；当前静态导出与 GitHub Pages 足够。
7. **运营节奏**：每月来源抽查、每季度依赖升级、每次发布 smoke check；见 [OPERATIONS](OPERATIONS.md)。

## 5. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 来源覆盖不足 | 读者把 `seed` 当定论 | UI 标 `seed/disputed`；路线图把来源覆盖列为 M4 首项 |
| 页面数量与 3D 资源增长 | 构建时间、移动端流量 | 检索按需加载；3D 延迟加载；每季度复测 |
| GitHub Pages 限制 | 大仓库/大产物 | 静态导出、资源哈希；必要时迁 CDN |
| 内容编辑引入模板句 | 可读性下降 | `language:check` + EDITORIAL 禁用清单 |
| 单人维护 | 文档与内容漂移 | `docs:check` 数量/版本校验 + OPERATIONS 周期维护 |
