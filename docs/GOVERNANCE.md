# 内容治理与合规

> 可信度是本项目的立身之本。本文定义来源分级、争议处理、双语审校与版权边界。

## 1. 来源分级

| 级别 | 来源 | 使用方式 |
| --- | --- | --- |
| **S** | 官方动画画面、官方设定集、官网机体页、模型说明书 | 可直接作为参数依据，必须记录具体出处（作品/集数/页码） |
| **A** | 权威百科、官方授权出版物、设定考证书 | 可作为佐证，需与 S 级交叉验证 |
| **B** | 社区 Wiki、论坛整理、模型店资料 | **只作为线索**，必须回溯到 S/A 原文后才能录入 |
| **C** | 个人博客、视频解说、社交媒体 | 不录入数据，可作为写作参考 |

**当前覆盖（V1）**：只有 `Machine` 与 `Event` 强制 `sources`。`Faction` / `Character` / `Work` / `Place` / `Tag` 目前通过作品与纪元锚定，尚未逐条挂 `source_refs`。文案与 README 不得把这种情况说成“全部条目附出处”；补全计划见 ROADMAP 的 M4。

红线：

- 不直接抓取或复制他人数据库/整理成果。
- 不把 B 级来源当最终依据。
- 不把机翻稿冒充人工校订稿。
- 不使用官方美术、模型、扫描设定集作为自有资产。

## 2. 参数与争议

- 参数缺失就留 `null`，UI 显示“资料未载”。禁止用同类机体估算。
- 同一参数在不同作品/设定集中冲突时：
  1. 在 `sources` 中并列双方；
  2. `disputed: true`；
  3. 在描述中说明差异，不择一当定论；
  4. 对比面板遇到缺失/争议字段时跳过或标注，不画成 0。
- `dataQuality: verified` 只用于已逐项核对到具体出处的条目；新条目默认 `seed`。

## 3. 正史层级

每条内容挂 `canon`：

- `mainline`：正史主线
- `side_story`：外传
- `parallel`：平行世界/其他纪元
- `game_original`：游戏原创

界面用不同底色标签提示，避免把平行设定当正史讲。跨纪元比较只通过技术标签与明确设定关联，不虚构因果。

## 4. 双语审校

- 日语原始资料 → 中文重写 → 术语表校验 → 日语回填 → 双语审校。
- 同一实体的中文/日文文本中，型号、数值、年份、专有名词必须一致。
- 术语表：机体名、势力名、技术术语各一张；机翻与人工都必须走表。
- 日文原文保留官方写法；中文是受控译文，不逐句直译。
- 缺译时显示“资料整理中”，不得用机翻冒充人工稿；机翻必须标 `mt: true`。

## 5. 人物与关系

- 只收录有明确设定依据的关系：亲属、师徒、战友、宿敌、仰慕。
- 不根据“看起来关系很好”推断。
- 人物所属支持多段任期（`affiliations`），转阵营必须带时间段。
- 结局状态以官方记录为准；“下落不明”用 `missing`，不写 `dead`。

## 6. 版权与商标

- 高达系列及相关名称、设定、角色、机体设计归创通・Sunrise / Bandai Namco 所有。
- 本项目为非商业、非官方粉丝考据项目，不从事销售、广告变现或付费订阅。
- 不使用官方 logo 作为项目标识；站点使用自制的轨道标记。
- 不使用官方美术素材、模型、扫描设定集；2D 设计图为自制示意图，标注“同人绘制，非官方设定图”。
- 文本基于事实重写；参数可引用数值，但表述与版式必须自制。
- 每个页面页脚保留非官方声明；仓库根目录 [NOTICE](../NOTICE) 提供完整说明。

## 7. 侵权处理

如权利方认为某条目超出合理使用：

1. 在 GitHub 开 issue，标明条目与权利依据；
2. 维护者在 72 小时内下架相关内容或替换为自制表述；
3. 在 CHANGELOG 记录变更，不悄悄删除；
4. 若涉及整站，优先保留技术架构与自有代码，移除争议内容。

## 8. 审核角色与节奏

| 角色 | 职责 |
| --- | --- |
| 编辑（Editor） | 提交内容、附出处、跑校验 |
| 二审（Reviewer） | 核对出处、数值、双语一致性 |
| 发布（Maintainer） | 合并、打 tag、触发部署 |

V1 不开放公众直接编辑，只接受带出处的建议稿/issue。内容变更走“编辑提交 → 二审核对出处 → 发布”三步。

## 9. 版本与可追溯

- 每次发布打 tag（如 `v1.2.0`），CHANGELOG 记录内容与代码变更。
- 未来引入 `content_version` 不可变快照与 `?v=` 历史查看。
- 数据修正必须保留旧值说明（`disputed` 或 CHANGELOG），不做无记录覆盖。

## 10. AI 与自动化

- 允许用脚本做格式校验、重复检测、单位换算、双语平行校验。
- 不允许用生成模型批量编造参数、出处或人物关系。
- 任何 AI 辅助文本必须经人工核对出处后才能进入 `verified`；未核对前保持 `seed`。
