# 机体覆盖表：这次到底补了什么

> 一句话：**11 个正史纪元的高达型主线机体已补齐到 147 台，其中 145 台属于这 11 个纪元；A.A. 是 2 台原创扩展。** 这不是 5,000+ 全衍生型号图鉴，而是一份可逐台打开、可追溯出处的“主线 + 核心外传”档案。
>
> 数据快照：2026-11-12。数量变化后请同步本页与 `docs/CHRONOLOGY.md`。

## 1. 收录规则

一台机体进入本档案，需要同时满足：

1. **有明确作品归属**：TV、OVA、剧场版，或官方漫画／小说／游戏等核心外传。
2. **有可读的机体身份**：有正式名称或型号，不是纯背景板。
3. **有至少一条可核对的设定线索**：作品正片、官方机体页、设定资料或模型说明书。
4. **不是纯换色／纯装备包**：同一台机体的不同背包、不同涂装，原则上合并到本体页；只有结构、定位或剧情意义明显不同时才单列。
5. **参数可以缺失**：没有可靠数值就写 `null`，界面显示“资料未载”，不估算。

### 为什么 C.C. 只有 2 台？

C.C. 的核心就是 **∀高达** 与 **Turn X**。前者是高达，后者严格说不是“高达”，但它是 C.C. 的另一极，所以保留。这个纪元不是“数量少所以没补”，而是作品本身只围绕这两台机体展开。

### 为什么 U.C. 有 38 台，而 F.C. 只有 12 台？

U.C. 横跨 0223 年、二十多部作品，机体谱系最长；F.C. 只有一部 TV、一届武斗会，主要机体就是各国代表机与恶魔高达。**覆盖是否完整，不能只看数量，要看作品与叙事节点是否都有对应机体。**

## 4. 明确不包含

- **5,000+ 全衍生型号**：MSV、游戏原创、模型原创、外传每一个换装都单列，会变成另一套数据库；本仓库不复制外部索引。
- **SD／BB 战士／Build 系列**：跨作品、规则不同，不放进正史纪元表。
- **纯换色与纯装备包**：例如同一台机体的不同涂装、同一背包的不同挂载，原则上合并。
- **没有正式名称的背景机体**：除非它在叙事中有明确作用。
- **官方美术与模型**：本站视觉是自绘 SVG／程序化 3D，不使用官方图。

## 5. 如何验证“补全”不是口号

```bash
npm run validate      # schema、外键、谱系无环、双向关联
npm run typecheck
npm run build         # 147 台机体的静态页面全部生成
```

打开 `/zh/chronology/`，页面底部有**按纪元分组的全机体总表**；每台机体都能点进详情页，查看势力、初登场、作品、武装、谱系边与出处。数量、名称、年份都由内容数据生成，不靠手工表格对齐。

## 6. 新增一台机体时

1. 先判断它是否满足上面的收录规则；如果只是换装，优先补到本体页的武装／描述。
2. 复制 `docs/templates/machine.template.json` 到 `content/machines/<slug>.json`。
3. 填写 `eraId`、`factionId`、`workIds`、`sources`；没有的参数写 `null`。
4. 如有驾驶员，补 `content/characters.json` 的 `machineIds` 并保持双向。
5. 跑 `npm run validate && npm run build`，再更新本页与 `docs/CHRONOLOGY.md` 的计数。
