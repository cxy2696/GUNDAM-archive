# 编辑风格：准确、简短、可读

> 本页是内容编辑的**语言门禁**。目标是**准确、简短、可读**。`content/` 下的中日文本与 `src/lib/i18n.ts` 的界面文案都遵守这套规则；`pnpm language:check` 会在 CI 中检查高频 AI 腔。

## 1. 三条优先级

1. **事实优先**：型号、年份、阵营、结果不能为了句子好听而改动。
2. **一句一件事**：长句拆开；能用名词就不用形容词堆叠。
3. **删掉结论**：写完事实就停，不替使用者总结“这意味着什么”。

## 2. 不要用的句式

| 不要写 | 原因 | 改成 |
| --- | --- | --- |
| “不是 A，而是 B” | 先立靶再推翻，像模型在制造转折 | 直接写 B；A 只在确实需要澄清时另起一句 |
| “真正的……” | 空泛的强调，没有信息 | 写具体属性： “实战型”“量产规格”“指挥官机” |
| “这台机体……” 连续出现 | 指代单调，像模板 | 用“该机”“它”或直接写型号 |
| “故事”“叙事”“读者” | 把设定当作文本分析 | 写“事件”“记录”“使用者” |
| “宿命”“极致”“浪漫”“见证了” | 抒情词替代事实 | 写“最终交战”“最大规模”“参加了” |
| “让人/令人……” | 替使用者规定感受 | 写动作或结果 |
| “仿佛/像……一样” 连用 | 比喻堆叠，信息密度低 | 保留一个最准确的比喻，或直接描述外形 |
| “不仅……而且……” | 常见模板转折 | 拆成两句，或只留后半句 |
| “这意味着/可以说/无疑” | 评论腔 | 删除，或写具体后果 |

> 日文同样避免“本当の”“物語”“読者”“宿命”“極限”“ロマン”等模板词；用作品内术语和具体动作。

## 3. 长度

- 机体 `summary`：中文 ≤ 90 字，日文 ≤ 120 字。
- 任何段落：中文 ≤ 260 字，日文 ≤ 320 字。
- 事件 `detail`：1–2 段，先背景/经过，再结果；不要复述 `summary` 和 `outcome`。
- 人物 `bio`：1–2 段，写“做了什么、为什么”，不写“他代表了什么”。

## 4. 事实与不确定性

- 参数没查到就写 `null`，不估算。
- 年龄、军衔、出身没有明确设定时写“不详”；有推定值时写“约”，不要写成确定值。
- 制作背景（作品、年份、媒体）与剧内事实分开写，不混成一句。
- 不把粉丝推论写成官方设定；有争议时在 `sources` 并列，并标 `disputed`。
- 不把“可能”“据说”留在一手资料语气里。

## 5. 双语

- 中文是重写，不是逐句直译；日文用自然的技术日语，不出现简体中文词。
- 型号、年份、数值、专有名词在中日文本中必须一致。
- 日文避免“〜という物語”“読者”“私たち”等把内容当评论的写法。

## 6. 改写示例

**Before**

> 它并不是一台单纯的兵器，而是把驾驶员的意识直接接入战场的高风险接口。这台机体真正的价值，在于它让 Newtype 的感知变成了可用的战术。

**After**

> 机体把驾驶员的脑波直接接入火控与推进系统。Newtype 的感知因此可以用于瞄准和回避，但驾驶员也要承受同样的数据负荷。

**Before**

> 这场战役见证了联邦与吉翁的宿命对决，也把整个战争推向了极致。

**After**

> 联邦与吉翁把残余舰队投入阿·巴瓦·库。战役以吉翁指挥体系崩溃结束，双方舰艇损失都很重。

## 7. Review 清单

- [ ] 删掉“不是…而是”“真正的”“故事”“宿命”“极致”等模板句
- [ ] 每段只讲一件事，首句有具体信息
- [ ] 没有替使用者下结论
- [ ] 年龄/军衔/年份有出处或标“约/不详”
- [ ] 中日文型号、数值、年份一致
- [ ] `pnpm language:check` 通过
